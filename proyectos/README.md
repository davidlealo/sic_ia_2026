# Proyecto final · SIC IA 2026

El proyecto final es requisito para la certificación. Cada equipo resuelve un **problema real** aplicando lo visto en el curso: machine learning, deep learning, PLN o IA generativa. Pueden usar datos sintéticos, pero el problema no puede ser inventado.

## Entregables (los seis son obligatorios)

| Entregable | Qué debe tener |
|---|---|
| **Informe final** | Problema, por qué importa, datos usados, modelo, resultados con métricas y comparación con un modelo base, limitaciones y próximos pasos |
| **Presentación final** | Máximo **10 minutos**, con estructura de pitch: gancho, problema, solución, prototipo y cierre. Muestren el código |
| **Prototipo** | La solución funcionando. La interfaz es libre: Gradio, Streamlit, Shiny, una web u otra |
| **Repositorio** | El código ordenado, con un README que explique cómo correrlo |
| **Plan de acción** | Qué se hace, quién lo hace y para cuándo, hasta la entrega |
| **WBS** | Planilla del Capstone: desglose de tareas tipo carta Gantt |

## Criterios que conviene tener presentes

- **Expliquen su código.** Pueden usar modelos externos y herramientas de IA, idealmente gratuitas, pero el equipo tiene que poder explicar qué hace cada parte y por qué. Las preguntas de evaluación se centran en el código.
- **Las métricas se interpretan según el problema.** No hay un umbral fijo: comparen con un modelo base y expliquen qué significa el número. Una métrica demasiado alta también merece revisión.
- **Los errores dicen qué datos faltan.** Revisen el balance de clases y los casos donde el modelo falla antes de cambiar de modelo.
- **La rúbrica es una guía.** Úsenla ítem por ítem para ver qué falta, pero lo central es cómo abordan el problema.

## Cómo subir su proyecto aquí

1. Hagan **fork** de este repositorio.
2. Creen una carpeta `proyectos/<nombre_del_equipo>/` con su README, el informe y el link al repositorio o al prototipo.
3. Abran un **pull request** hacia este repositorio.
